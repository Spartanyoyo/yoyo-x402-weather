日期：2026 年 10 月 16 日。除原始 JSON 中的 UTC 时间外，本文时间均为北京时间。

本文保留首次验收结果。2026-10-22 的完整复核、修复、新部署及测试情况见[复核报告](第一阶段_复核报告_2026-10-22.md)。

第一阶段技术流程已完成：用户用自然语言提出“查询北京现在的天气”，Codex 阅读我们编写的 F-02，按文档组织参数，通过自有云端天气服务取得 HTTP 402，使用测试钱包支付 0.001 测试 USDC，随后获得 HTTP 200 和真实天气模型数据。链上回执、USDC 转账事件及双方余额一致，A1–A10 均有项目内实测证据，供 mentor 复核。

F-01 是上游提供商文档的接入依据，见 [F-01](F-01_upstream.md)。F-02 是我们为 C 编写的接口文档；本机文件为模板，云端返回时自动填入实际服务地址和收款方。此次演示已实际读取云端完整文档，并非仅引用 README。

## 3. 从自然语言到付费请求

1. 用户原话：**查询北京现在的天气**。
2. 通过 Open-Meteo/GeoNames 核对北京首都记录 `1816670`，按 F-02 将代表坐标整理为 `latitude=39.9075&longitude=116.3972`。[地点来源与选择记录](../evidence/transactions/location-beijing.json)保留原始结果；该坐标不代表用户实际定位。
3. 20:58:22，买方工具读取云端 F-02，保存读取时间、全文及 SHA256。
4. 对 C 发出下列请求，未携带付款凭证时收到 HTTP 402；报价包含网络、资产、收款地址和 1000 最小单位金额。
5. 官方客户端根据报价创建测试钱包签名并重试同一请求；取得 HTTP 200、天气内容与支付回执。
6. 查账确认链上交易成功，金额、付款人和收款人与报价一致。

```http
GET https://yoyo-x402-weather.accessible-trip.workers.dev/weather?latitude=39.9075&longitude=116.3972
```

完整过程：[本次云端购买记录](../evidence/transactions/purchase-1792155501626.json)，状态为 `verified`。成功响应中的 `requestId` 与 HTTP `X-Request-Id` 一致，为 `95b137d9-aff5-4d56-9cf6-1f185f9079c5`；同一记录保存支付响应头、解码回执、天气和链上交易。

## 7. 失败记录与能力边界

云端一共执行了两次购买尝试，仅第二次产生实际付款。第一次因公共 facilitator 报 `replacement transaction underpriced` 而未成功结算，未返回天气。先等待原授权于 20:57:50 过期，再于 20:58:03 核实授权未用、双方余额未变且无匹配转账，才重新发起购买。[失败记录](../evidence/history/purchase-1792155166089.json)与[到期后核对](../evidence/history/reconciliation-1792155483822.json)完整保留。

本阶段是应用集成与交易验证。卖方为按规则响应的程序，尚不包含自主议价、复杂协作或生产级可用性承诺。公用天气源、测试网、公共 RPC 与 facilitator 的可用性会影响后续演示；服务异常时应先保存结果并查账。钱包私钥与 Cloudflare Token 留在本机配置中，未放入公开文档、代码或云端 Worker。
