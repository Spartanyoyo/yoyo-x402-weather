## 已发现并修复的问题

| 问题 | 原来的影响 | 修复后的行为 |
|---|---|---|
| 非 GET 方法未阻断 | 未付款 HEAD 会进入天气处理逻辑 | 返回 405 和 `Allow: GET`，不调用天气或结算 |
| 坐标解析过宽 | 十六进制、科学计数法和重复参数可被接受 | 只接受一个十进制数字坐标，错误在付款前返回 400 |
| 天气校验不足 | 缺湿度或风速、无效时间、陈旧数据可能成为付费结果，并先写入缓存 | 核对字段、单位、来源、位置和时间；通过后才缓存，否则返回 502 且不结算 |
| 正文先于支付回执保存 | 正文损坏时可能漏记已经收到的结算回执 | 先持久化回执，再解析正文；付款成功但交付失败单独标记 |
| 买方异常证据不完整 | 付费响应丢失后难以检查原授权，容易误重试 | 保存授权编号、金额、有效期等公开字段，不保存完整可重放签名 |
| 购买请求可能重复 | 异常恢复时可能再次签名或提交付费请求 | 每次购买最多一个签名、一次付费提交；付费请求不自动重试 |
| 免费请求连接不稳 | 读取文档或未付款报价时一次网络抖动就会中止流程 | 文档和未付款报价各允许一次有记录的只读重试；签名后仍不重试 |
| 查账条件不足 | 天气缺失或区间有抵消转账时，可能只凭余额误判成功 | 重查初始余额、分页扫描双方相关转账，并分别核验付款和天气交付 |
| 免费探测只看 HTTP 状态 | 空文档、错误收款方或错误报价也可能被标为通过 | 校验文档、网络、资产、金额、收款方、资源 URL、请求编号与缓存头 |
| 本地 Worker 加载买方配置 | Wrangler 可能把 `.env.local` 的买方密钥加入本地 Worker | 使用 `.dev.vars` 和空 `secrets.required`；本地与云端只绑定公开 `SELLER_ADDRESS` |
| 单个公共 RPC 易被限流 | 预检查或付款后查账会因一个节点不可达而中断 | 默认维护 8 个有序 Base Sepolia 公共 RPC，逐级切换；每个节点每次调用最多尝试一次，成功后停止 |

天气有效性规则为：最近预报时次与请求时刻相差不超过 90 分钟，模型更新时间不超过 24 小时。历史记录按原响应时间核验，不按今天的时间重新判定旧预报。
